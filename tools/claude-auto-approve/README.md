# حارس أذونات Claude Code

أداة تقرأ كل طلب إذن يعرضه Claude Code، **تفهم ماذا يعني**، تعطيه **تصنيفاً
عربياً**، ثم تقرّر:

- **قبول** → تضغط `Always allow` تلقائياً (أو الخيار الوحيد إن كان واحداً)
- **رفض** → **بطاقة في زاوية الشاشة** فيها شرحٌ عربيّ لما يريده Claude Code،
  وحكمُ كلّ جزء من الطلب، والاقتراح — والقرار لك

**بلا أي صوت.** اللون وحده هو التنبيه.

---

## البطاقة: ماذا يريد Claude Code، وما اقتراح الأداة

لكل طلب تشرح الأداة نيّته بالعربية، وتفصّل أجزاءه، وتقترح:

```
⚠  طلب جزئيّ
يريد: 3 خطوات متتالية: تجهيز تغييرات git ثم تدمير تاريخ git

  ✅ git add .            تجهيز تغييرات git — تجهيز «.» للحفظ في الالتزام القادم
  ✅ git commit -m fix    تجهيز تغييرات git — حفظ التغييرات كنقطة ثابتة
  ⛔ git push --force     تدمير تاريخ git — رفع قسري يمحو تاريخ الفرع على الخادم

الاقتراح: الموافقة على البعض — 2 من 3 أجزاء آمنة، والباقي يحتاج قرارك

  [ وافق مرة واحدة ]   [ اقبل دائماً ]   [ ارفض دائماً ]   [ تجاهل ]
```

ثلاثة اقتراحات ممكنة:

| الحكم | متى | لون البطاقة |
|---|---|---|
| **الموافقة على الكل** | كل أجزاء الطلب آمنة | لا بطاقة — يُوافق تلقائياً |
| **الموافقة على البعض** | جزء آمن وجزء لا | برتقالي |
| **الرفض** | لا شيء منه آمن | أحمر |

---

## التعلّم: ما تحسمه مرة، لا تُسأل عنه مرة أخرى

أزرار البطاقة تعلّم الأداة قرارك:

- **«اقبل دائماً»** → يُحفظ الأمر ويُوافق عليه تلقائياً بلا بطاقة في المرات القادمة
- **«ارفض دائماً»** → يُرفض بصمت في المرات القادمة
- **«وافق مرة واحدة»** → لا يُحفظ شيء

القرارات تُخزَّن في `learned.json`. لمراجعتها أو حذفها: انقر `memory.cmd`.

### قيدان يحفظان الأمان

**١. «اقبل دائماً» متاح فقط لما رُفض بسبب «لا أعرف هذا الأمر».**
إن رُفض الطلب بقاعدة خطر صريحة — حذف، تسريب، أسرار، صلاحيات — فالزرّ
**لا يظهر أصلاً**. إلغاء قاعدة خطر يحتاج تعديلاً واعياً في `DANGER_RULES`،
لا نقرة زرّ في لحظة استعجال.

**٢. القرار المحفوظ يُعاد فحصه كل مرة.**
لو تغيّر الأمر أو تحدّثت قواعد الخطر بحيث صار الأمر المحفوظ خطِراً،
تُهمَل الذاكرة وتظهر البطاقة من جديد.

---

## لا تتنقّل معك

الأداة تجد نافذة Claude Code **بالاسم** وتلتصق بها. تنقّلك بين التطبيقات
والمواقع لا يعنيها: لا تقرأ نافذةً أخرى ولا ترسل مفتاحاً إليها أبداً.

وتصلك البطاقة الحمراء **أينما كنت** — تظهر في زاوية الشاشة التي عليها مؤشّر
فأرتك، فوق أيّ تطبيق تعمل عليه، دون أن تسحب التركيز منك.

**قاعدة أمان مهمّة:** الموافقة لا تُرسَل إلا ونافذة Claude Code هي النشطة.
إن ظهر طلب آمن وأنت في تطبيق آخر، تنتظر الأداة عودتك ثم توافق — حتى لا
تذهب الضغطة إلى ما تكتب فيه أنت.

## مثال على ما تعرضه

في نافذة الأداة:

```
[14:02:11] ✅ قبول: [تشغيل الاختبارات] Bash npm test → Always allow
[14:02:19] ✅ قبول: [قراءة ملفات] Read src/index.ts → Always allow
[14:02:28] ⏳ بانتظارك: [بناء المشروع] Bash npm run build — سأوافق حين تعود
[14:02:34] ⛔ رفض: [حذف ملفات] Bash rm -rf node_modules
           السبب: حذف متكرّر أو قسري — قد يمحو عملاً غير محفوظ بلا رجعة
```

وفي زاوية شاشتك تظهر بطاقة حمراء فيها: «طلب مرفوض» · التصنيف · السبب ·
نصّ الأمر · «انقر لإخفاء البطاقة».

لرؤية التصنيفات قبل التشغيل: انقر `check.cmd`، أو افحص أمراً بعينه:

```bash
python demo.py "git push --force"
```

## التصنيفات

| مقبول تلقائياً | مرفوض دائماً |
|---|---|
| قراءة ملفات | حذف ملفات |
| بحث في الكود | كتابة مباشرة على القرص |
| فحص حالة git | تدمير تاريخ git |
| جلب تحديثات git | وصول إلى أسرار وبيانات اعتماد |
| تجهيز تغييرات git | إرسال بيانات إلى الخارج |
| تشغيل الاختبارات | تنفيذ كود من الإنترنت |
| فحص جودة الكود | رفع الصلاحيات |
| بناء المشروع | تحكّم بالنظام |
| تثبيت حزم المشروع | نشر إلى سجلّ عامّ |
| معلومات النظام | تعديل قاعدة البيانات |
| تعديل ملفّ مشروع | تعديل ملفّ الأذونات |
| | مسار حسّاس |
| | طلب شبكة خارجي |
| | **أمر غير معروف** |

آخر صفّ هو الأهمّ: **ما لا تفهمه الأداة ترفضه.** لا يُقبل إلا ما هو معروف صراحةً.

قاعدة «تعديل ملفّ الأذونات» مقصودة: تمنع تعديل `.claude/settings.json`
و`.mcp.json` — أي توسيع الصلاحيات من خلف ظهرك.

## طرق التشغيل

### ١. بالنقر المزدوج (الأسهل)

| الملف | ما يفعله |
|---|---|
| **`run.cmd`** | التشغيل الاعتيادي: يقبل الآمن، ويعرض بطاقة حمراء للمرفوض |
| `preview.cmd` | معاينة: يعرض قراره دون أن يضغط شيئاً |
| `trust.cmd` | يقبل **ويرفض** بنفسه — بعد أن تثق بقراراته |
| `check.cmd` | يعرض جدول التصنيفات فقط، بلا تشغيل |
| `memory.cmd` | يعرض القرارات المحفوظة ويحذف ما تريد |
| `test.cmd` | يشغّل كل اختبارات الأداة |

### ٢. من سطر الأوامر

```bash
pip install -r requirements.txt
python claude_auto_approve.py                 # الاعتيادي
python claude_auto_approve.py --dry-run       # معاينة
python claude_auto_approve.py --auto-deny     # يرفض بنفسه
python claude_auto_approve.py -i 2 --no-edits # فحص كل ثانيتين، بلا تعديل ملفات
```

### ٣. تلقائياً مع ويندوز

انقر **`add-to-startup.cmd`** مرة واحدة — يبدأ الحارس مع كل تشغيل للجهاز
في نافذة مصغّرة. للتراجع: `remove-from-startup.cmd`.

### ٤. من داخل الأداة

بعد تشغيلها تبقى في الانتظار، وتتحكّم بها من أي مكان:

| الاختصار | الوظيفة |
|---|---|
| **`Ctrl+Alt+S`** | تشغيل / إيقاف مؤقّت |
| **`Ctrl+Alt+Q`** | إنهاء الأداة |

هذان الاختصاران يعملان في أي تطبيق، ولا يتعارضان مع مفاتيح `F` المحجوزة
لوظائف اللابتوب.

### الخيارات

| الخيار | المعنى |
|---|---|
| `--dry-run` | معاينة: يعرض قراره دون أن يضغط شيئاً (أو `preview.cmd`) |
| `--auto-deny` | يرفض بنفسه (`Esc`) بدل تركه لك — أو `trust.cmd` |
| `--no-edits` | لا يوافق تلقائياً على كتابة/تعديل الملفات |
| `-i 3` | الفاصل بين الفحوص بالثواني |
| `--window claude` | جزء من عنوان النافذة المراقَبة |
| `--toast-seconds 0` | إخفاء البطاقة بعد ثوانٍ. `0` = تبقى حتى تُحسم |

### متى تختفي البطاقة الحمراء

لا تختفي بمرور الوقت. تبقى أمامك حتى:

- **تختار في نافذة Claude Code** — تختفي وحدها فور اختفاء الطلب
- **أو تنقر عليها** لإخفائها يدوياً

وإن ظهر طلب مرفوض جديد، تحلّ بطاقته محلّ القديمة.
(لو أردت الإخفاء التلقائي رغم ذلك: `--toast-seconds 15`)

### من التنبيه إلى القرار

**ابدأ بالوضع الافتراضي:** عند الرفض تظهر البطاقة الحمراء وتقرّر أنت بنفسك.
جرّبه مدةً وراجع `auto_approve.log`.

**حين تثق بقراراته:** شغّل `trust.cmd` (أو `--auto-deny`) فيتولّى الرفض بنفسه
ولا يقاطعك — وتبقى البطاقة الحمراء لإعلامك بما رفض.

كل القرارات تُسجَّل في `auto_approve.log`.

## إضافة أوامرك الخاصة

افتح `classifier.py`:

- لقبول أمر إضافي → أضف سطراً في `SAFE_RULES` مع تصنيفه العربي
- لرفض نمط إضافي → أضف سطراً في `DANGER_RULES`

ثم شغّل `python test_classifier.py` للتأكّد أن شيئاً لم ينكسر.

## ما اختُبر وما لم يُختبر

**مُختبَر آلياً:** محرّك التصنيف كاملاً، اكتشاف نافذة الإذن، استخراج الأمر،
التوجيه حسب نوع الأداة، تحليل الأجزاء، دورة حياة البطاقة، ودورة التعلّم
كاملةً (يظهر ← تعلّم ← يُطبَّق تلقائياً). انقر `test.cmd` أو:

```bash
python test_classifier.py     # ٨٣ حالة تصنيف
python test_prompts.py        # ١٨ نافذة إذن
python test_lifecycle.py      # ٩ خطوات: متى تظهر البطاقة ومتى تختفي
python test_memory_flow.py    # ١٤ حالة تعلّم وذاكرة
```

**غير مُختبَر — يحتاج ويندوز حقيقياً:** إيجاد نافذة Claude Code وقراءتها عبر
UI Automation، ورسم البطاقة الحمراء، وإرسال المفاتيح. جرّب `preview.cmd` أولاً
للتأكّد من أن الأداة تقرأ نوافذك قبل تفعيل الضغط.

## تحذير

الأداة تُلغي المراجعة البشرية عن الطلبات التي تصنّفها مقبولة. التصنيف اجتهاديّ
وقد يخطئ. راجع `auto_approve.log` دورياً.

البديل الأمتن تقنياً: **hooks** من نوع `PreToolUse` داخل Claude Code — تقرأ نصّ
الأمر الحقيقي لا الواجهة، ولا تتأثّر بتغيّر الشكل أو دقّة الشاشة.
راجع `/permissions` و`/fewer-permission-prompts`.
