# حارس أذونات Claude Code

أداة تقرأ كل طلب إذن يعرضه Claude Code، **تفهم ماذا يعني**، تعطيه **تصنيفاً
عربياً**، ثم تقرّر:

- **قبول** → تضغط `Always allow` تلقائياً (أو الخيار الوحيد إن كان واحداً)
- **رفض** → إطار أحمر + التصنيف + **سبب الرفض**، ولا تضغط الموافقة

تعمل على نافذة Claude Code وحدها؛ إن كانت النافذة النشطة شيئاً آخر فلا تفعل شيئاً.

---

## مثال على ما تعرضه

```
[14:02:11] ✅ قبول: [تشغيل الاختبارات] npm test  →  Always allow
[14:02:19] ✅ قبول: [قراءة ملفات] cat src/index.ts  →  Always allow
[14:02:34] ⛔ رفض: [حذف ملفات] rm -rf node_modules
              السبب: حذف متكرّر أو قسري — قد يمحو عملاً غير محفوظ بلا رجعة
              الإجراء: توقّفت الأداة — قرّر بنفسك ثم Ctrl+Alt+S للاستئناف
```

لرؤية التصنيفات قبل التشغيل: انقر `check.cmd`، أو افحص أمراً بعينه:

```bash
python demo.py "git push --force"
```

## التصنيفات

| مقبول تلقائياً | مرفوض دائماً |
|---|---|
| قراءة ملفات | حذف ملفات |
| بحث في الكود | كتابة مباشرة على القرص |
| فحص حالة git | تدمير تاريخ git |
| جلب تحديثات git | وصول إلى أسرار وبيانات اعتماد |
| تجهيز تغييرات git | إرسال بيانات إلى الخارج |
| تشغيل الاختبارات | تنفيذ كود من الإنترنت |
| فحص جودة الكود | رفع الصلاحيات |
| بناء المشروع | تحكّم بالنظام |
| تثبيت حزم المشروع | نشر إلى سجلّ عامّ |
| معلومات النظام | تعديل قاعدة البيانات |
| تعديل ملفّ مشروع | تعديل ملفّ الأذونات |
| | مسار حسّاس |
| | طلب شبكة خارجي |
| | **أمر غير معروف** |

آخر صفّ هو الأهمّ: **ما لا تفهمه الأداة ترفضه.** لا يُقبل إلا ما هو معروف صراحةً.

قاعدة «تعديل ملفّ الأذونات» مقصودة: تمنع تعديل `.claude/settings.json`
و`.mcp.json` — أي توسيع الصلاحيات من خلف ظهرك.

## التشغيل

```bash
pip install -r requirements.txt
python claude_auto_approve.py
```

على ويندوز: انقر `run.cmd`.

### الخيارات

| الخيار | المعنى |
|---|---|
| `--dry-run` | معاينة: يعرض قراره دون أن يضغط شيئاً (أو `preview.cmd`) |
| `--auto-deny` | عند الرفض يضغط `Esc` تلقائياً بدل انتظار قرارك |
| `--no-pause` | لا يتوقّف بعد الرفض، ينبّه ويتابع |
| `--no-edits` | لا يوافق تلقائياً على كتابة/تعديل الملفات |
| `-i 3` | الفاصل بين الفحوص بالثواني |

**السلوك الافتراضي عند الرفض:** ينبّه ويتوقّف ولا يضغط شيئاً — يترك القرار لك،
لأن الرفض التلقائي قد يعطّل عملاً مشروعاً. فعّل `--auto-deny` إن أردته يرفض بنفسه.

### التحكّم

`Ctrl+Alt+S` تشغيل/إيقاف · `Ctrl+Alt+Q` إنهاء

كل القرارات تُسجَّل في `auto_approve.log`.

## إضافة أوامرك الخاصة

افتح `classifier.py`:

- لقبول أمر إضافي → أضف سطراً في `SAFE_RULES` مع تصنيفه العربي
- لرفض نمط إضافي → أضف سطراً في `DANGER_RULES`

ثم شغّل `python test_classifier.py` للتأكّد أن شيئاً لم ينكسر.

---

## ما اختُبر وما لم يُختبر

**مُختبَر آلياً (١٠١ حالة):** محرّك التصنيف كاملاً، اكتشاف نافذة الإذن،
استخراج الأمر، التوجيه حسب نوع الأداة.
شغّلها بنفسك: `python test_classifier.py` و`python test_prompts.py`.

**غير مُختبَر — يحتاج ويندوز حقيقياً:** قراءة نصّ النافذة عبر UI Automation،
ورسم الإطار الأحمر، وإرسال المفاتيح. جرّب `preview.cmd` أولاً للتأكّد من
أن الأداة تقرأ النوافذ عندك قبل تفعيل الضغط.

## تحذير

الأداة تُلغي المراجعة البشرية عن الطلبات التي تصنّفها مقبولة. التصنيف اجتهاديّ
وقد يخطئ. راجع `auto_approve.log` دورياً.

البديل الأمتن تقنياً: **hooks** من نوع `PreToolUse` داخل Claude Code — تقرأ نصّ
الأمر الحقيقي لا الواجهة، ولا تتأثّر بتغيّر الشكل أو دقّة الشاشة.
راجع `/permissions` و`/fewer-permission-prompts`.
