# حارس أذونات Claude Code

أداة تراقب نوافذ أذونات Claude Code، **تقرأ نصّ الطلب وتصنّفه**، ثم:

- **طلب آمن معروف** → تضغط `Always allow` تلقائياً (أو الخيار الوحيد إن كان واحداً)
- **طلب خطِر أو مجهول** → **إطار أحمر حول الشاشة** + صافرة + توقّف الأداة، ولا تضغط شيئاً

تعمل على نافذة Claude Code وحدها؛ إن كانت النافذة النشطة أيّ شيء آخر فلا تفعل شيئاً.

---

## المبدأ الحاكم: الشكّ يعني التوقّف

الأداة **لا توافق إلا على ما تعرفه صراحةً**. أي طلب لا يطابق قائمة السماح —
حتى لو بدا بريئاً — يُصنَّف تنبيهاً. هذا يعني تنبيهات زائدة أحياناً،
وهو الاتجاه الصحيح للخطأ: أن تسأل بلا داعٍ خيرٌ من أن توافق على ما لا ينبغي.

### ما يُنبَّه عليه دائماً

| الفئة | أمثلة |
|---|---|
| تدمير الملفات | `rm -rf` · `del /f` · `Remove-Item -Recurse` · `dd if=` |
| تدمير في git | `push --force` · `reset --hard` · `clean -fd` · الدفع إلى `main` |
| الأسرار | `.env` · `.ssh/` · `.aws/` · `id_rsa` · `api_key` · `password` |
| تسريب البيانات | `curl -d` · `scp user@host:` · `nc` · `base64 \| ...` |
| تنفيذ من الإنترنت | `curl \| bash` · `Invoke-Expression` · `powershell -enc` |
| الصلاحيات والنظام | `sudo` · `chmod 777` · `net user` · `shutdown` · `reg delete` |
| النشر الخارجي | `npm publish` · `docker push` |
| قواعد البيانات | `DROP TABLE` · `db reset` · `DELETE FROM` بلا شرط |
| **ملفّ الأذونات نفسه** | `.claude/settings.json` · `.mcp.json` |
| مسارات حسّاسة | `.github/workflows` · `System32` · `/etc/` · ملفّ `hosts` |
| الشبكة الخارجية | `WebFetch` · `WebSearch` |
| **أي أمر مجهول** | كل ما ليس في قائمة السماح |

قاعدة `.claude/settings.json` مقصودة تحديداً: تمنع توسيع الصلاحيات من خلف ظهرك.

### ما يُوافَق عليه تلقائياً

أوامر قراءة وفحص فقط: `git status/diff/log`، `ls`، `cat`، `grep`، `rg`،
`npm test/lint/build`، `pytest`، `tsc --noEmit` وما شابه — إضافةً إلى
قراءة وتعديل ملفات المشروع الاعتيادية (`.ts`، `.tsx`، `.py`، `.md`...).

## التشغيل

```bash
pip install -r requirements.txt
```

### ١. ابدأ بوضع المراقبة (إلزامي)

```bash
python claude_auto_approve.py
```
أو انقر `run-watch.cmd`. لا يضغط شيئاً — يسجّل فقط ما **كان** سيفعله في
`auto_approve.log`. اتركه يوماً في عملك الطبيعي وراجع السجلّ.

### ٢. فعّل الضغط بعد أن تطمئن

```bash
python claude_auto_approve.py --live
```
أو انقر `run-live.cmd`.

### الخيارات

| الخيار | المعنى | الافتراضي |
|---|---|---|
| `--live` | فعّل الضغط الحقيقي | معطّل (مراقبة فقط) |
| `--no-edits` | لا توافق على كتابة/تعديل الملفات | التعديل مقبول |
| `-i, --interval` | الفاصل بين الفحوص بالثواني | `3` |

### التحكّم

`Ctrl+Alt+S` تشغيل/إيقاف · `Ctrl+Alt+Q` إنهاء

بعد كل تنبيه أحمر تتوقّف الأداة تلقائياً حتى تراجع الطلب وتستأنف بنفسك.

## ما اختُبر وما لم يُختبر

**مُختبَر آلياً (١٠١ حالة، `python test_classifier.py` و`python test_prompts.py`):**
محرّك التصنيف بكامله، واكتشاف نافذة الإذن، واستخراج الأمر، والتوجيه حسب نوع الأداة.

**غير مُختبَر — يحتاج ويندوز حقيقياً:** قراءة نصّ النافذة عبر UI Automation،
ورسم الإطار الأحمر، وإرسال الاختصارات. لهذا وضع المراقبة هو الافتراضي.

---

## البديل الرسمي (أفضل تقنياً)

Claude Code يدعم **hooks** من نوع `PreToolUse` تقرأ نصّ الأمر الحقيقي —
لا صورة الشاشة — وتقرّر السماح أو المنع برمجياً. لا تتأثّر بتغيّر الواجهة
ولا بدقّة الشاشة. راجع `/permissions` و`/fewer-permission-prompts` داخل
Claude Code. هذه الأداة حلٌّ خارجيّ يعمل من فوق الواجهة، وهي بطبيعتها
أقلّ متانة من الـ hooks.

---

## تحذير

الأداة تُلغي خطوة المراجعة البشرية عن الطلبات التي تصنّفها آمنة. التصنيف
اجتهاديّ وقد يخطئ. راجع `auto_approve.log` دورياً، ولا تستخدمها في مستودع
يحتوي أسراراً حقيقية أو صلاحيات إنتاج قبل أن تتحقّق من سلوكها عندك.
